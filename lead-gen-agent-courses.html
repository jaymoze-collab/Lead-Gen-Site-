Combining Skills & Subagents
Master Claude Code · Skills
Foundation
Build specialist agents — researcher, writer, outreach agent — each equipped with custom skills and run in parallel across your prospect list.
  • Skills hold specialized logic (ICP rules, messaging guidelines, research criteria)
  • Sub-agents are parallelized instances that execute that logic at scale
  • Link skills to sub-agents via frontmatter: skills: [prospect-researcher]
  • Sub-agents do NOT inherit skills from parent — must be explicitly declared
  • Sub-agents can fix side issues (errors, gaps) autonomously during execution

Context Window Management
My Daily Workflows · Feb 2026
Foundation
Long-running agent systems will degrade without context discipline. Keep your orchestrator lean by offloading to sub-agents.
  • AI is most capable in the first 30–40% of a fresh context window
  • Start a new session after planning; don't mix planning + execution in one window
  • Never load raw data (logs, prospect lists) into main session — use sub-agents
  • Use a "Plan File" to carry context across sessions without re-explaining everything
  • Monitor context % in the status bar; restart if it jumps unexpectedly

Memory for Scheduled Tasks
Master Claude Code · Automation
Pipeline
Give your pipeline agent persistent memory across runs so it tracks contacted prospects, sent messages, and completed actions without repeating itself.
  • Cloud tasks have no memory by default — use Airtable or Neon/PlanetScale as memory layer
  • Prompt: "Check previous records at start, log new actions on completion"
  • Configure Airtable connector with create + read-only permissions
  • For local tasks, writing to a local file is simpler and sufficient
